# Working rules

## Mission alignment

Every active project must name which program outcome it serves:

- realistic-size separation;
- stronger general theory; or
- boundary testing and alternative routes.

It must also state a theorem target, quantitative consequence, and stop or
pivot condition.  Interesting algebra without one of these links remains a
diagnostic, not a round-three result.

Use `PROJECT_BRIEF_TEMPLATE.md` when opening a substantial new calculation.
Its mission question and decision fields must be filled before the project is
promoted to the plan.

## Correctness labels

Every quantitative statement must be labeled as one of:

- proved for arbitrary physical diagonal weights;
- proved for uniform orbit weights only;
- exact finite-\(q\) computation;
- certified numerical bound;
- exploratory numerical optimization; or
- conjectural extrapolation.

Do not cite a weaker label as evidence for a stronger one.

## Falsification first

- Every spectral reduction must reproduce \(q=2,4\) exactly.
- Every weighted theorem must face concentrated and correlated physical laws.
- Every adaptive square function must face the existing two-node witness.
- Every improved exponent must have a loss ledger and a candidate saturator.
- Every alternative hard instance must use the common OP3-8 scorecard.
- Every purported counterprotocol must satisfy the actual passive hard-dose
  model.
- A failed theorem target is recorded, not silently weakened.

## Quantitative relevance

For finite-size work, track the actual TV ledger at \(N=1024\).  For
asymptotic work, state the resulting transcript scale and dose exponent.  For
boundary work, state exactly which conjecture, route, or resource distinction
the evidence tests.

## Portfolio discipline

- The signed-permutation route is the current lead project, not a permanent
  commitment.
- A route stops when a physical counterexample or certified budget makes its
  target impossible.
- Negative results count when they close a real route and support a decision.
- Exploratory searches are bounded by a named hypothesis and search space.
- At each major gate, update `STATUS.md` and the relevant decision record.
- At each program review, update `MISSION_LEDGER.md` even when the result is
  negative; the ledger records the answer and decision, not just successes.
- A finite-\(q\) sequence is not a scaling law.  When its next size controls a
  route decision, record that computation as an explicit gate and do not
  extrapolate across nonmonotone values.

## Artifact policy

- `notes/`: proofs, counterexamples, loss ledgers, scorecards, and decisions.
- `searches/`: deterministic exploratory calculations with explicit scope.
- `tests/`: regressions for accepted identities and preserved witnesses.
- `STATUS.md`: accepted benchmark, track states, lead blocker, and next review.
- `OPEN_PROBLEMS.md`: current theorem targets and acceptance gates.

Do not copy round-two code unless it is being modified.  Reference the frozen
sibling folder to avoid divergent duplicate implementations.
