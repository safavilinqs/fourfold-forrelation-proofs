# Round 3 plan

Date: 2026-07-15

## Operating model

Round three is a portfolio with three tracks.  Track A is the near-term lead
because it has an explicit \(N=1024\) target and inherited calculations.
Tracks B and C prevent one hard instance or one contraction lemma from
becoming the entire program.

At each review, compare work against the main question: does it establish,
strengthen, explain, or seriously test the active--passive separation?
`PORTFOLIO.md` turns this rule into one bounded live project per track.

## Program-level outputs

The round should produce more than a collection of local lemmas.  Maintain
five program outputs in `MISSION_LEDGER.md`:

1. a best-known theorem statement with honest constants and scope;
2. a finite-size verdict at the \(N=1024,D=6\) benchmark;
3. an upper/lower-bound map for both passive and active dose;
4. a mechanism statement that survives the physical and adaptive models; and
5. a route decision supported by positive or negative evidence.

Track A primarily supplies output 2, Track B supplies outputs 1 and 4, and
Track C supplies outputs 3 and 5.  A result should be copied into the mission
ledger only after its proof label and consequence are explicit.

Maintain the four-sided comparison in `BOUNDARY_MAP.md`: passive lower,
passive upper/protocol, active lower, and active upper/protocol.  The current
program is strongest in the first and fourth cells.  Round 3 should not call
the boundary understood while the passive protocol frontier and the general
active lower frontier remain blank.

## Program review loop

After each decisive theorem or falsification gate:

1. update the bound map before choosing another calculation;
2. ask whether the result changes scale, finite-size relevance, an algorithmic
   frontier, mechanism, or hard-instance choice;
3. compare continuing the current route with one named alternative;
4. select one bounded project with an acceptance gate and stop rule; and
5. preserve at least one live challenge to the lower-bound picture, either a
   passive protocol search, an active improvement, or a saturating witness.

This review loop prevents a long series of local orbit bounds from becoming
the program by inertia.

## Portfolio review and resource rules

Review after each major theorem gate or falsification, not after a fixed
amount of algebra.

- Keep Track A as the lead while OP3-3 has a credible path to the finite-size
  constant.
- Maintain at least one precisely stated Track B target.
- Use Track C to challenge assumptions and to prepare a pivot, not as an
  unbounded search over examples.
- Stop a route when its physical counterexample or certified budget cannot
  meet the main threshold.
- Promote results only when their proof status and quantitative consequence
  are explicit.
- Do not let local progress in Track A indefinitely postpone a bounded Track
  B or C falsification project.  At every major Track A gate, select one
  concrete next experiment outside Track A.
- Use `PORTFOLIO.md` as the live queue: one finite deliverable in each track,
  with no unbounded alternative-instance sweep.
- Judge a negative result by the decision it enables: continue, strengthen,
  pivot, or stop.
